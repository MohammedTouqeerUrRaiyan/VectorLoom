# 1. What is the Salesforce Security Model?

## Definition

The **Salesforce Security Model** is a framework that determines:

* **Who can log in**
* **What objects they can access**
* **Which fields they can see**
* **Which records they can access**
* **What actions they can perform**

Think of Salesforce security as **multiple security gates**. A user must pass through each gate before accessing data.

> ⭐ **Important Keyword:** **Layered Security**

---

# 6. Organization-Wide Defaults (OWD)

## Definition

**Organization-Wide Defaults (OWD)** define the **default level of access** users have to records they do not own.

> ⭐ **Important Keyword:** **Baseline Record Access**

---

## Think of OWD as the starting point.

Example

```
OWD

↓

Private
```

Everyone starts with **Private** access.

Additional access is granted later.

---

## Types of OWD

| OWD                  | Meaning                      |
| -------------------- | ---------------------------- |
| Private              | Only owner can access        |
| Public Read Only     | Everyone can view            |
| Public Read/Write    | Everyone can view and edit   |
| Controlled by Parent | Child inherits parent access |

---

# Common Interview Questions

## Q1. What are the four levels of Salesforce Security?

**Answer**

1. Organization Level
2. Object Level
3. Field Level
4. Record Level

---

## Q2. What is OWD?

**Answer**

Organization-Wide Defaults define the **default record access** for users who do not own a record.

---

## Q3. Difference between Profile and Role?

| Profile                    | Role                                    |
| -------------------------- | --------------------------------------- |
| Controls what users can do | Controls which records users can access |

---

## Q4. When should Sharing Rules be used?

**Answer**

When users in different roles need access to records that Role Hierarchy does not provide.

---

## Q5. Can Permission Sets increase Record-Level Security?

**Answer**

No.

Permission Sets grant **object, field, and system permissions**, but they do **not** share records. Record sharing is controlled by **OWD, Role Hierarchy, Sharing Rules, Manual Sharing, and Teams**.

## 💡 Interview Scenario

**Question:** *Your company's Opportunity OWD is set to **Private**. Rahul (Sales Executive) creates an Opportunity. The Sales Manager should automatically see it, Finance should have read-only access to all Opportunities, and Priya (another Sales Executive) should temporarily help Rahul on just this one Opportunity. How would you configure Salesforce?*

**Answer:**

1. **Profile** – Give Rahul and the Sales Manager object permissions to read/edit Opportunities.
2. **OWD** – Set Opportunity access to **Private**.
3. **Role Hierarchy** – Place the Sales Manager above Rahul so the manager automatically inherits access.
4. **Sharing Rule** – Create an owner-based or criteria-based sharing rule to give the **Finance** team **Read Only** access.
5. **Manual Sharing** – Rahul shares the specific Opportunity with **Priya** for temporary collaboration.

This layered approach is a textbook example of how Salesforce's **data security model** works in real-world implementations.
